# Japan Railway 3D Simulator

駅と日時を指定し、日本の実際の線路形状に沿って列車を走らせる静的Webアプリです。経由駅を複数指定でき、検索した複数の列車を同じ時計で同時に再生できます。

左側で駅・経由駅・日時を入力し、候補を選択します。中央に3D地図、下部に列車と再生操作、右上にシミュレーション時刻を表示します。モバイルでは「経路検索」でパネルを開きます。

## 起動

Node.js 22 LTSを推奨します。プロジェクトのフォルダで実行してください。

```powershell
npm install
npm run dev
```

表示されたローカルURLをブラウザで開きます。WindowsのPowerShellでスクリプト実行ポリシーのエラーが出る場合は、`npm` の代わりに `npm.cmd` を使えます。

```powershell
npm run test
npm run build
npm run preview
```

`dist/` が静的な公開用ファイルです。ファイルを直接開く場合はモジュールやデータ取得が制限されるため、ローカルサーバー経由で閲覧してください。APIキー・AWS登録は不要です。

## 操作できる機能

- 日本語駅名の候補、会社別・同名駅の区別、出発駅と到着駅の交換
- 経由駅の追加、指定順の変更、削除、順序を守る経路探索
- 出発・到着日時の指定、最大3件の経路候補、途中停車駅・乗換・待ち時間の表示
- 営業日、曜日、祝日、24時以降の便に対応する時刻表検索
- 検索した列車の追加・削除、複数列車の同時走行と共通時刻でのシーク
- N02やGTFSの実線形、5種類のオリジナル3D車両、4両編成、前照灯・尾灯・窓
- 一時停止・再開・前後の駅へ移動・到着へ移動、1〜200倍速
- 季節・緯度・経度・日時による昼夜の変化、昼・夕方・夜の固定表示
- 追従・空撮・運転席・全体俯瞰・自由カメラ、距離・俯角の調整
- 大阪駅周辺の実在建物、地理院地図、配信可能な範囲のPLATEAU地形・建物
- 駅の情報と運行日の駅時刻表、既存の乗換案内と公式時刻表へのリンク
- 検索条件のローカル保存、経由駅付きURL共有、全画面表示
- 外部配信障害・WebGL非対応時の日本語メッセージと簡易地図

複数列車を試すには、候補を選んで「この列車を同時走行に追加」を押し、別の候補を選んで再生してください。別の駅・時刻で検索した列車も追加できます。同じ便は重複登録を防ぎます。時間軸は追加した全列車の発着を含み、追加列車は発車前と到着後に非表示になります。

## 駅時刻表と乗換案内の反映

実際の事業者データを使う路線を優先します。検索結果と再生には同じ列車の停車時刻列を使います。出典と収録期間は画面の「データ情報」と各区間の詳細から確認できます。

| 区間 | 収録内容 |
| --- | --- |
| 京都市営地下鉄 烏丸線・東西線 | 2026年3月14日改正の公式CSV、平日・土休日・上下の時刻 |
| 神戸市営地下鉄 西神・山手線・北神線 | 2025年3月15日改正の公式CSV、途中始終着を含む便 |
| 神戸市営地下鉄 海岸線 | 2026年3月13日までの旧表。現在の日付では収録便がありません |
| 岡山電気軌道 東山線・清輝橋線 | 公開GTFSの実時刻、運行日・追加日・運休日 |
| 明知鉄道 明知線・急行 | 2026年3月14日改正GTFS、各駅停車・急行 |
| 伊勢鉄道 伊勢線 | 2026年3月14日改正GTFS、普通・特急南紀／快速みえの伊勢線区間 |
| 富山地方鉄道 市内軌道線・富山港線 | CC0 1.0のGTFS、環状線・直通便を含む |
| とさでん交通 路面電車 | CC BY 4.0のGTFS、運行便ごとの枝線を判定 |
| 豊橋鉄道 渥美線・市内線 | CC BY 4.0のGTFS、運動公園前・赤岩口方面の枝線を判定 |
| JR・阪急・近鉄など | 停車パターン、線形距離、代表所要時間を基にしたシミュレーションダイヤ |

京都・神戸の収録上限は2026年12月28日です。未確認の年末年始への適用を避けるための収録範囲として設定しました。岡山の同梱版は2026年11月1日〜2027年10月31日、明知鉄道・伊勢鉄道は2026年3月14日〜2027年3月31日、富山は2026年3月14日〜2027年3月13日、とさでんは2026年8月1日〜2027年4月30日、豊橋鉄道は2026年1月8日〜2027年4月24日のデータです。原表に発時刻だけがある駅では着発を同じ分で扱います。

大阪〜京都は新快速・快速・普通の停車駅と所要時間の違いを反映しています。JRなどの個々の列車の発車分・運賃・番線は未収録です。各候補から、同じ条件で既存の乗換案内を開けます。[時刻表の出典・収録範囲・再生成](docs/TIMETABLE_SOURCES.md)

## 対応地域

駅を検索できる対象地域は、近畿6府県、中国5県、四国4県、中部・北陸9県の計24府県です。N02の接続形状から抽出した系統と明示的に定義した系統を合わせ、N02由来データは4,586駅・364系統・5,794区間です。別データの岡山電気軌道も含みます。

大阪〜京都・神戸・奈良・和歌山・姫路・名古屋・岡山・広島・高松、および京都〜金沢を自動テストで確認しています。追加系統からは大阪メトロ・北大阪急行、近鉄名古屋線、明知鉄道、伊勢鉄道、一畑電車、静岡鉄道、富山地方鉄道、名鉄・名古屋市営地下鉄、東京メトロ・京王井の頭線も検索テストしています。金沢方面は敦賀で乗り換えます。

## データを更新する

加工済みの軽量データは `public/data/` に含まれます。原版の全国ZIPや都市全体の3Dモデルを配布する必要はありません。

- 駅・路線は国土数値情報 N02 2025年度版。取得と変換は [鉄道データ手順](docs/NETWORK_DATA.md)。
- 事業者の時刻表は `python scripts/prepare-timetables.py --download`。詳細は [時刻表手順](docs/TIMETABLE_SOURCES.md)。
- 大阪建物の加工は `node scripts/prepare-osaka.mjs`。PLATEAUの北区LOD1から周辺2.6km四方だけ抽出します。
- 大阪道路・水域の加工は `python scripts/prepare-streets.py`。OSMから取得する独立したODbLデータです。
- オリジナル車両は `node scripts/prepare-trains.mjs` で生成します。
- 推定運行間隔・走行時間・停車時間・最低乗換時間は `src/settings.json` で変更します。

データの再取得にはインターネット接続が必要です。改正データを取り込む際は停車順、運行日、許諾条件も確認してください。[データの出典とライセンス](docs/DATA_SOURCES_AND_LICENSES.md)

## テスト

`npm test` は実線形、停車駅、実ダイヤのカレンダー、経由指定、乗換、日跨ぎ、複数列車の共通時計、カーブ上の車両位置、季節の太陽高度を検証します。`npm run build` はTypeScript検証と静的ビルドを実行します。ブラウザの操作・描画については [検証結果](docs/VERIFICATION.md) を参照してください。

## 公開

GitHubの公開先は [kosukechun/Japan-Railway-3D-Simulator](https://github.com/kosukechun/Japan-Railway-3D-Simulator) です。`main` へのpushでテスト・ビルドを実施し、GitHub Pagesへ配信するワークフローを含みます。初回のPages設定は [GitHub Pages公開手順](docs/DEPLOY_GITHUB_PAGES.md) に記載しています。サブパスに対応し、条件共有にはクエリ文字列を使います。

AWS Amplifyを使わずに公開する場合は、ローカルでテスト・ビルドし、`dist/` の中身を非公開のAmazon S3バケットへアップロードして、Amazon CloudFrontから配信できます。GitHub連携は不要です。操作手順は [AWSコンソール初心者ガイド](docs/AWS_CONSOLE_GUIDE.md) に記載しています。S3・CloudFrontの利用量に応じて料金が発生する場合があります。今回の実装ではAWSの課金リソースを作成していません。

## 既知の制約・今後の課題

- 全国全駅・全列車と全私鉄のダイヤ、リアルタイム運行・遅延、正規運賃、番線、列車予約は未実装です。
- 各路線の実ダイヤを含む収録期間外は便が出ません。公式の改正データへの更新が必要です。
- 地下・高架・トンネルの標高と上下別走行線は簡易表現です。地表の標高に合わせるため、実際の高架や地下を再現しない区間があります。
- 天王寺の紀州路快速は原典のホーム端点に約116mの差があり、構内で表示位置が切り替わります。
- 4両編成と停止・加減速は可視化モデルです。GTFSで同じ分に着く隣接停留場は、同一時刻に位置が切り替わります。
- 建物は大阪周辺を同梱し、それ以外は外部の3D Tiles配信に依存します。外部配信停止・CORS・端末のWebGL性能によって表示範囲が変わります。
- 地図画像の保存機能と列車の衝突・閉塞制御は未実装です。追加した列車の共通走行は各便の時刻に基づきます。

全国への拡張は系統別停車順と線形を追加し、再利用できるダイヤを同じ形式に変換する手順で行えます。大量の時刻表を収録する段階では地域・日付別の時刻表分割が必要です。[設計と拡張方法](docs/ARCHITECTURE.md)
