# 駅と線路のデータ

大阪・京都周辺では、同じ駅を通る普通・快速・新快速が、それぞれの停車駅を結びます。岡山から高松へ向かう列車は瀬戸大橋を渡り、京都から敦賀へ向かう特急は琵琶湖の西側を通ります。駅間の曲線は国土交通省の鉄道データから取り出しました。

## 出典と利用条件

国土交通省「国土数値情報（鉄道データ）」2025年度版を加工して作成しました。基準日は2025年12月31日、公開更新は2026年4月です。公式ページに示された利用条件は CC BY 4.0 です。出典・ライセンス・加工したことを表示すれば、商用利用、複製、加工、再配布ができます。アプリを転載する場合もこの表示を引き継いでください。[国土交通省のデータ詳細・利用条件](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html) ／ [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.ja)

N02には路線名や駅のホームに相当する線はありますが、列車の発着時刻や列車ごとの停車駅は含まれません。運転系統は別に定義しました。たとえば阪急京都線特急は大阪梅田、十三、淡路などに停車し、近鉄京都線は普通と急行で停車順が変わります。実際の運転パターンの一部を採用しています。[JR西日本の停車駅案内](https://www.jr-odekake.net/route/) ／ [阪急の停車駅案内](https://www.hankyu.co.jp/privace/info/index.html) ／ [近鉄の停車駅案内](https://www.kintetsu.co.jp/railway/rosen/stop.pdf) ／ [JR四国の快速マリンライナー](https://www.jr-shikoku.co.jp/01_trainbus/vehicle-info/marine.html)

## 収録範囲

N02から作った現在の配布データには4,586駅、364系統、5,794の系統別駅間区間を収録しています。同じ線路を走る複数種別では、区間をそれぞれ数えます。対象24府県の境界とN02の接続形状から299系統を自動抽出し、明示的に定義した系統を加えました。時刻表が未収録の系統は、停車パターンとシミュレーションダイヤを使います。

## Windows での再生成

配布用の加工済みファイルはリポジトリに含まれています。開発者が路線を追加したり、原典と照合したりするときに以下を実行します。

1. 国土交通省の鉄道データ詳細ページで「2025年度」の行から `N02-25_GML.zip` をダウンロードします。全国版は約14 MBです。対象地域を自動抽出する場合は、行政区域データの2025年版から `N03-20250101_24_GML.zip` と `N03-20250101_54_GML.zip` ～ `N03-20250101_58_GML.zip` も取得します。[N02公式ページ](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html)・[N03公式ページ](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2025.html)
2. Python 3.11 以上を用意し、PowerShellでこのリポジトリのフォルダーを開きます。変換に追加のPythonパッケージは不要です。
3. 以下のコマンドでデータを作り直します。保存場所が異なる場合はZIPのパスを書き換えます。

   ```powershell
   python scripts/prepare-network.py "$env:USERPROFILE\Downloads\N02-25_GML.zip" --boundaries "$env:USERPROFILE\Downloads\N03-20250101_24_GML.zip" "$env:USERPROFILE\Downloads\N03-20250101_54_GML.zip" "$env:USERPROFILE\Downloads\N03-20250101_55_GML.zip" "$env:USERPROFILE\Downloads\N03-20250101_56_GML.zip" "$env:USERPROFILE\Downloads\N03-20250101_57_GML.zip" "$env:USERPROFILE\Downloads\N03-20250101_58_GML.zip"
   ```

4. 画面に各系統の停車駅数と線形距離が表示されます。最後まで正常に終了したら、次のコマンドで全区間の参照・端点・距離を検証します。

   ```powershell
   npm install
   npm test -- tests/network.test.ts
   ```

再生成前に新旧の結果を比べる場合は、`--out 比較用フォルダー` を指定してください。使用した公式ZIPのSHA-256は `AAF76AF133B2E771E538FABC4646D2E443DC1D5A67B221382A28D744E706CC9F` です。PowerShell の `Get-FileHash` で、取得したファイルが同じか確認できます。

## 変換処理

1. ZIP内のUTF-8版GeoJSONから、鉄道区間と駅を読み取ります。座標の順序は経度、緯度です。N02の座標系はJGD2011です。
2. `scripts/service_patterns.py` に定義した事業者名と原典の路線名を組み合わせ、系統ごとに該当する線だけを抽出します。例えば「新快速」の線路にはJR西日本の東海道線と山陽線を使います。
3. 原典の線に含まれる連続する頂点をグラフの辺にし、延長を計算します。原典の駅形状と路線形状で一致する頂点を探し、ホームの中央に近い候補を選びます。別駅の線を距離だけでつなぐ処理はありません。
4. 停車駅を順番に処理して、Dijkstra法で線路上の最短経路を求めます。通過駅では線形を保ったまま通過します。線路の接続が見つからない、駅の識別子が衝突する、前区間との端点が意図せず離れるといった場合は変換を停止します。
5. `public/data/network.json` に軽量な駅情報と運転系統を保存します。境界ZIPを渡すと、指定した対象府県内のN02線形から連続した駅列を自動抽出します。自動抽出系統は路線・駅形状であり、列車種別ごとの停車駅や運転時刻ではありません。`public/data/shapes/<系統ID>.json` には、その系統の線形を順方向で格納します。逆方向の列車は同じ形状を逆順で利用できます。距離の単位はkmで、表示する模型上の線形長を表します。

駅名の一致は個別に確認します。京都市営地下鉄「十条」と近鉄「十条」には異なる駅IDと座標を与えました。JR「三ノ宮」と地下鉄「三宮」も別々に保存しています。乗換徒歩は検索側で定義します。

## 精度と収録上の制約

- 駅は系統ごとにホーム近くの線路上で停車します。駅を示す代表マーカーと別ホームのモデルの間に差が出る場合があります。
- 天王寺の紀州路快速では、N02上で環状線側と阪和線側のホーム形状が約116m離れ、構内の渡り線を追跡できません。駅構内の切り替わりとして扱い、両端を結ぶ新しい線路は生成していません。
- 同じ線を往復に使うため、上下別の走行線、個々の番線、トンネル内の高さは簡易表現です。運賃計算用の営業キロや列車の行先別の細かな番線違いは含みません。

## 全国への追加

`scripts/service_patterns.py` に、追加する系統の固有ID・事業者・原典の路線名、停車駅順、駅ごとの都道府県を記載します。遠い同名駅や近接する別駅には `STATION_IDS` で異なる識別子を指定します。原典の同一路線に同名駅が複数ある場合は、候補の抽出条件を駅コード（`N02_005c`）まで絞るよう変換器を拡張してから追加してください。

公式の経路案内で停車順と接続を照合し、生成スクリプトを実行します。検索に使う時刻データは別途追加します。利用条件と運行日を確認できる時刻表を優先し、時刻表がない場合はシミュレーションダイヤの速度・間隔などを設定します。既存の地域を変更せずに系統単位で線形を追加でき、元の全国ZIPをサーバーに置く必要はありません。
